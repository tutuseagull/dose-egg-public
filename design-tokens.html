DoseEgg Design Tokens

The token set the prototypes are built from. Two layers: primitives hold raw values, semantic tokens name roles. Every name should survive a palette change; if changing a value forces renaming a token, the token was named wrong.

Current look, decided 2026-10-09 in Timeline v4. Oat neutrals for the ground, one blue hue (227°) for every accent, Manrope for all type, and depth only on the layers that float.

How it got here: oat + petrol (2026-08-05) → Stitch blue (2026-08-06, the domain lead's preference) → matched (2026-10-09). Stitch's band nearly vanished on its own bluish page (1.07:1); a warm page gives a cool band something to stand against. Stitch's button blue sat 15° warmer than its band and leaned teal beside it, so matched puts the whole ramp on one hue. The losing palettes are in archive.html and git history.

Source of truth: tokens.css, one file linked by this page, Timeline v4 and Look Back. Change a value there and every screen follows. A prototype may add its own layout tokens, but never redefines one of these.

Borders: three, by what the line is for

TokenContrast on whiteUse
--border-subtle1.26:1Dividers. Decorative, never a control's edge.
--border-control1.5:1The hairline on a flat control whose label or icon already says it is a control: log tiles, nudges, chips, med rows.
--border-interactive3.75:1Where the line is the only cue: an empty text field, the hollow assumed mark, the dashed unknown mark.

Open, flagged 2026-10-09: is 1.5:1 enough? --border-control came with flat controls the same afternoon. WCAG 1.4.11 asks for 3:1 only where the boundary is needed to identify the component, and these controls carry a label, so it arguably passes. But Parkinson's reduces contrast sensitivity, and this page has always treated faint edges as a serious finding. The previous lifted style was no better (about 1.2:1 plus a shadow). Options: keep 1.5 with the label rule above, move to --border-interactive (3.75, reads outlined and busier), or a tonal fill. Worth asking P01 to find the tiles in a sheet on a bad day.

Material and elevation

Depth belongs to a layer, not to what is inside it. Whatever floats on its own gets a shadow; its contents stay flat. Decided 2026-10-09 from a study of ChatGPT on iOS: one raised thing per layer reads as calm hierarchy, while a raised button inside a raised sheet is two depths competing. It also fixed a quiet bug: a lifted chip looked more "on" than a selected flat one.

Glass rules

  • Navigation layer only. Never on content: text that something else shows through is text competing with a label [C-16].
  • Fill at least 74% white, blur 20px with a saturation lift, so whatever passes behind is a soft wash, not legible text. One hairline, no lit top edge.
  • Reduce Transparency makes it solid white (the media query above).
  • The header has no background of its own. The card's band sits in the page and scrolls away under it; once scrolled, a soft page-coloured wash fades in behind the header, the same job the dock's wash does at the bottom.

Interaction states

StateRule
Press:active, always. The one feedback every input method gets.
HoverOnly inside @media (hover: hover). iOS keeps :hover on the last thing tapped, so an ungated hover becomes a stuck highlight. Hover is extra, never the only signal.
Focus--focus-ring outline for keyboard and switch control; --focus-glow for fields that show focus inside their own edge. Not optional: tremor makes touch unreliable.
SelectedAccent edge (inset 0 0 0 1px var(--accent) plus accent border), 6.9:1 on white. Selection is never carried by fill alone.

Entry marks and epistemic state

One mark colour; the icon carries the type. The five-hue set was retired on 2026-08-06 because it collapsed to 1.00 to 1.14:1 under every type of colour-vision deficiency.

The basis field (docs/entry-schema.md) is drawn as fill and outline, never as hue, so it reads as certainty, not quality. There is no token that could make an assumed dose look taken.

AssertedSolid. The person said so.
AssumedHollow. Planned, no answer.
UnknownDashed. We cannot know.
DeclinedRinged. Reported not taken.

Pending (added 2026-10-09) is not a basis. A dose that has fallen due and is still waiting for its answer is assumed, drawn hollow, with a Not confirmed label. Pending is a view flag on the live slot only and is never exported.

Big numerals, where a number is the point

Manrope's figures are the part of the face worth showing off. Parked for Look Back: where a statement turns on a number, the number can be set large, tabular, at display size.

Text size and system scaling

Every size is rem, so the whole scale moves from one root value. Never build a second hardcoded set of sizes.

html { font-size: 100%; }                               /* one knob */
html[data-text-scale="large"]  { font-size: 112.5%; }
html[data-text-scale="larger"] { font-size: 125%;   }
html[data-text-scale="huge"]   { font-size: 150%;   }
html[data-text-scale="max"]    { font-size: 200%;   }   /* WCAG 1.4.4 corner case */

Follow the system scale where the platform allows, and ship an in-app control: reading ability varies between ON and OFF within one day. Layouts must survive 200%: no fixed-height text containers, no truncation, no single-line assumptions. Anything that depends on a measured height (the header band) is measured at runtime, never written as a number.

The rule that matters most

A day with no data must never be drawn as a value. The same week both ways; Wednesday was not logged:

Wrong: missing drawn as zero

Wednesday reads as the best day of the week. It is a lie, and the kind that ends up in front of a neurologist.

Right: missing drawn as a gap

The reader sees absence of data, not absence of symptoms. Same dashed-hollow language as unknown.

At most four series, always with direct labels or shape, never a colour-only legend. No severity gradients: a sequential colour scale is a ranking, and a ranking is a verdict [C-08]. Chart text sits at the 14px floor like everything else.

Deliberately absent

What a token set refuses to name matters as much as what it names. Adding any of these needs a decision, not a convenience:

  • No success, error or warning for health data. --feedback-error is for app failures only. There is no token for a body being wrong.
  • No severity scale. No red-amber-green. A scale invites ranking, and ranking is a verdict [C-08].
  • No adherence or completion colour. There is nothing to score [C-08].
  • No hover-only states. Revised 2026-10-09: hover may exist behind (hover: hover), as an extra. It is never the only signal.
  • No open shadow scale. Revised 2026-10-09: there are exactly three depth uses (glass, float, overlay), each argued for above. A fourth needs its own argument.

White on accent (the Taken button): 6.9:1. White icon on a mark: 8.5:1. --text-muted now passes on sunken too (5.1), so the v0 restriction on that pair is lifted.

Non-text (1.4.11): --border-interactive 3.75:1 on white, 3.6:1 on page; the epistemic outlines use it, because that distinction is what stops an assumed dose reading as taken. --border-control at 1.5:1 is the open question flagged under Borders.

Touch: 24px is the WCAG 2.2 AA bar; 48 and 56 are above it but below the smallest size in the Parkinson's targeting research (10mm), hence the tiers and touch-target-test.html.

The 2026-08-05 audit (Stitch blue) is in git history. Its two lasting findings live on above: borders split by role, and colour demoted below icon for entry type.
